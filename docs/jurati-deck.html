Intro

The work moved into agents. The context should move with it.

People use Claude Code, Cursor, Copilot, and other coding agents for real work now. Jurati brings the team's existing context into that workflow without making the person operate another system.

TodayPeople coordinate in Slack, issues, meetings, and personal recall, then paste the important parts into each agent.

The coordination problem

Agents should not start from zero.

Agent tools are good at the files in front of them. Teams also need them to know what already happened.

01
The same choices come backThe next agent suggests REST even after the team chose gRPC.
02
Work overlaps by accidentSomeone edits the auth module while another PR is already migrating it.
03
Useful rules get lostRollback notes, release checks, and validation steps live in people, not tooling.

What Jurati does today

It gives the agent team context before work starts.

Looks first

Before a task, the agent checks current work, decisions, workflows, and labeled PRs.

Finds specifics

The agent can search for a topic or read a remembered item by ID when it needs detail.

Remembers handoffs

Short-lived notes can cover blockers, current focus, or what to inspect next.

Saves decisions

Longer-lived decisions and workflows go through review in the knowledge repo.

Stays current

The server syncs from git and rebuilds its local index for fast reads.

Knowledge model

Some memories are temporary. Some deserve review.

Jurati tracks what kind of thing the agent is saving, and how carefully the team should review it.

P
PrincipleA rule the team wants agents to keep following.
D
DecisionA choice the team made, with the reason behind it.
W
WorkflowHow the team reviews, validates, ships, or responds.
J
ProjectWhat is in flight, blocked, or useful across repos.
A
ActiveA short-lived handoff or investigation note.
L0Temporary

Short-lived active notes, kept off the main branch.

L1Quick review

Project status and low-risk context updates.

L2Team review

Workflows and most decisions.

L3Careful review

Principles and highest-stakes decisions.

Architecture

Under the hood, it is just git and agent context.

The visible workflow stays simple. The implementation keeps shared context reviewable and the agent context fresh.

core/
Decides what should be remembered, what should stay quiet, and what needs review.
server.py
Gives agents context before work and lets them save useful team knowledge quietly.
git/
Keeps durable context in a normal repo, with branches and PRs for lasting changes.
providers/
Reads configured repos for PRs carrying the jurati label and turns them into context.

Translation layer

People say what matters. Agents handle the filing.

A person does not need to know where the note should live. The agent decides whether it is temporary context, a project update, or a reviewed decision.

1
"This PR changes the auth token contract."Human language, usually in the PR or the agent conversation.
2
The agent knows this is a team decision.Not a personal note, not a raw transcript, not a temporary scratchpad.
3
The context becomes reviewable.Durable knowledge lands in the knowledge repo instead of disappearing into chat.

Privacy boundary

People choose what gets broadcast.

Jurati uses explicit signals: labeled PRs and intentional agent writes. It does not mine everything people do.

NO
No broad miningUnlabeled PRs, chats, editor activity, and comments are not used.
NO
No read receiptsThere is no "who viewed this" surface.
NO
No presence trackingGit provenance is for accountability, not engagement analytics.
ID
Sensitive notes stay quietRestricted entries stay out of startup context and keyword search, but explicit read by ID is still possible.
